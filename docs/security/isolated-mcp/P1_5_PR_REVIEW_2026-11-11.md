# PR #131 合并前评审与 P2 准备

评审对象：PR #131 初始 HEAD `d68231f7c6e440b64d7c82beceb893b52d525133`，基于已核验 GitHub main `4b385fd11e2f617eee491781067b2f69cb8aa1be`。P1.5 修复提交及 CI/实测结论在本文件末尾追加。此处的两个 Git SHA 都不代表生产运行版本。

**关键修正：** 初始 P1 将严格协议边界与结果脱敏直接挂在共享 PersonalServer Handler 上，会改变旧内网 URL 的未知方法响应、参数接纳和正文输出。P1.5 评审确认这违反旧入口兼容要求：新增服务端只读路由 `/internal/mcp/isolated/personal`。外部8443仍为原建议路径，由 Nginx 精确改写到该路由。两条 Go 路由复用同一 PersonalServer、认证、Key、并发槽和知识权限；严格请求/结果/错误保护只作用于隔离路由，旧内网路径保留原协议与正文契约。客户端环境Header不参与路由或授权判断。

## 代码结论

| 关注点 | 评审结果及证据 |
|---|---|
| 原 PersonalServer 八工具 | `NewPersonalServer` 仍只注册 `list_knowledge_bases`、`search_knowledge`、`grep_chunks`、`list_documents`、`read_document`、`wiki_search`、`wiki_read_page`、`wiki_index`，两条 Go 路由共享实例、认证和知识服务，无第二套账号/Key。真实 Codex P1 八工具调用成功；P1.5 制品需复测。 |

| 协议兼容性 | Codex CLI 0.146.0 经测试HTTPS全部八工具成功，原生产HTTP入口在R2完成最小只读协议。POST JSON、通知202、GET/DELETE405符合当前无状态实现；[MCP 2025-06-18传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)允许无GET流时405。严格字段校验现仅在隔离路由，未来隔离客户端扩展仍需专门回归。 |

| 内容脱敏 | 原 Portal 纯文本投影继续防止签名URL/文件链接透传，隔离输出投影屏蔽裸绝对路径、保留相对Wiki slug、`knowhub:`引用和大整数ID。P1.5 发现中文标点后的正文被绝对路径正则误删，已添加失败用例并修复；修正后完整APP经真实HTTPS验证正常尾文保留、物理路径遮盖。旧HTTP仍返回原正文契约。 |
| 其他业务日志影响 | `WithPrivatePayload` 只在个人入口标记；通用Logger/GORM/LLM Debug/embedding Langfuse 对无该标记的原路径沿用原行为。单测以非私有日志及APM正向对照证明测试接收器工作；私有标记、测试Key、签名/路径标记在P1受控日志/APM均未发现。生产 WAF/APM/模型留存未知。 |
| 必要统计 | 原 usage collector未停用。`prepareInboundMCPEvent` 从认证上下文得用户、Key ID与租户，`observeTool` 仍记录固定工具/成功/耗时、目标和命中知识库。仅隔离路由把客户端自由输入的name/version降为`unknown`；旧内网路由的客户端统计行为保留。P1初始测试DB抽样为104条个人MCP事件、2个用户、2个Key、成功调用涉及8个工具、222条知识库资源关联；这些是修正前的抽样数，不作为P1.5最终计数。修正后合成标记不进入usage DB。 |
| 长期只读 | 既有 PersonalServer 独立于动态工作区目录，固定八工具+调用guard+隔离路由HTTP字段白名单均默认拒绝。未来内网上传须另建可写处理逻辑；若有人扩展此只读注册表，应由八工具数量/schema/未知写调用测试阻断。隔离入口不接受用户自报环境Header决定权限。 |

P1.5 另发现 `wiki_search` 复用了通用工具的“regex=true”说明，但个人服务原处理逻辑始终只允许字面搜索。这是已有的发现/处理不一致；本轮不改变原 tools/list schema，以保留内网旧客户端行为。隔离入口仍拒绝 `regex=true`，应在后续经内网客户端回归后另行修正文档或独立隔离 schema。
