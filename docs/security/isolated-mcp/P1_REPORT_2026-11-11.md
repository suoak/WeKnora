## 最小改造结果

继续使用现有 `PersonalServer`、现有个人 Key 认证和 `PortalMCPKnowledge` 检索/权限逻辑。没有创建第二个 MCP Server、员工身份、Key 体系或检索服务，没有新增数据库迁移。

八个工具固定为 `list_knowledge_bases`、`search_knowledge`、`grep_chunks`、`list_documents`、`read_document`、`wiki_search`、`wiki_read_page`、`wiki_index`。保留现有 `tools/call` guard，并在已有 Handler 前增加严格请求边界。请求必须是精确路径、单条合法 JSON-RPC、批准方法与字段，禁止未知工具、写工具、附件/URL/content/base64 等伪装字段、批量请求、重复 JSON 键、过深结构和超过 1 MiB 请求。正常 JSON-RPC POST 查询保留。

固定工具表和调用 guard 属于永久只读 PersonalServer，未来内网写工具必须通过独立可写处理逻辑提供，不能直接扩充此注册表。测试模拟未来工具注册及 ingest/chat 能力提升，确认 guard 拒绝且写 handler 计数为零。用户自带环境 Header 不参与只读授权。

成功结果继续使用既有授权知识投影，并对所有字符串补充 URL/绝对文件路径脱敏，保留相对 Wiki slug、`knowhub:` 引用及大整数身份。工具错误、panic 和个人入口中间件错误使用固定消息，避免反射路径、Key 或下游错误正文。

测试 Nginx 单独监听 8443，仅允许精确外部路径 `/api/v1/mcp/personal`。拒绝其他 REST/管理/文件/MCP 路径、multipart、二进制和压缩载荷；保留 GET/POST/DELETE 协议方法。关闭缓存、代理重放和请求/响应缓冲；限制速率、请求体、慢请求和并发。隔离流量全局最多占 4 个槽，现有 PersonalServer 总并发为 8；测试证实隔离慢查询达到上限时内网 HTTP MCP 仍可用。

## 日志与外部调用边界

个人入口在最前层标记私有载荷上下文，通用 Logger 不再采集请求/响应正文、查询串、认证头、客户端 Request-ID 或错误原文。请求日志只留固定入口、状态和耗时；允许受控调用计数、用户/Key ID 等既有元数据。忽略客户端任意 client name/version 的持久化，避免借初始化字段写入内容。

私有上下文延续至工具、GORM SQL、下游检索、LLM 调试文件及 embedding Langfuse；这些路径不持久化载荷。启用 debug、LLM_DEBUG_LOG 和本地 Langfuse 接收器，使用正常语义查询及拒绝载荷的合成敏感标记实测，而非只检查源码。另有非私有流量正向导出对照，证明测试接收器确实生效。Nginx 仅记录时间/状态/字节/耗时，错误日志关闭载荷输出。对应单元测试覆盖错误和 panic。

语义检索仍须将查询发送给已批准的 embedding 模型服务；本次复用现有检索契约，模型由测试环境受控模拟器承接。生产模型供应方、WAF、APM、镜像采集器等外部系统的留存策略尚未取得证据，不能以代码中的载荷屏蔽替代其验收。

“禁止上传”指没有创建文档、会话、文件、队列任务或可写代理能力。查询字段本身可携带任意文本，不能声称能识别并阻止所有编码内容进入进程内存；通过拒绝写入能力、禁止持久化正文、受控模型目的地和网络白名单共同约束通道。

## 验证与证据解释

最终验收使用真实编译的完整 APP，连接独立 PG/Redis；不是仅 mock Handler。另有 repository/服务级 fixture 作为写 handler 计数和协议边界对照。实际 Codex CLI 完成测试 TLS 下全部八工具调用。各项最终计数和二进制 SHA256 以证据 JSON 为准；测试脚本保留在本目录，私有运行目录、证书和新生成 Key 不入库。

业务副作用检查比较知识、Chunk、Wiki、Session、Message、资源、资源绑定、待办和死信共九张表的行数与内容摘要，检查独立文件目录和 12 类 Redis 业务任务。允许认证 last-used、计费/调用次数等受控元数据变化；不把它们混入“零业务写入”结论。生产 MinIO/S3 服务未接入测试，本次文件存储后端实测结果不代表生产桶策略。

早期运行中的失败没有改写为 PASS：旧主机 GCC9 无法链接 main 既有 DuckDB，改用已有 Bookworm 构建镜像；首次源码包缺少编译文档、测试挂载和 PG 就绪时序得到修正；CONNECT/工作区禁用的已有 HTTP 返回值和受保护日志读取方式修正了测试断言。随后发现 bare path 与错误反射风险，修改代码并重新构建、部署和验收。早期结果留在受控测试机历史目录，交付证据仅标识最终候选。
