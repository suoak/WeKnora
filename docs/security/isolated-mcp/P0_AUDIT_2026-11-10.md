## 4. Go MCP 和个人 Key 审计

### 4.1 实际代码与需求描述存在差异

`internal/router/routes_mcp_endpoint.go` 的 `RegisterMCPServerRoutes` 把 GET/POST/DELETE `/mcp/:endpoint_id` 绑定到 APP 内置 `internal/mcpserver.Server`。`internal/middleware/mcp_endpoint_auth.go` 只接受工作区端点 Bearer token，构造机器身份及端点 scope；**这不是个人 Key 身份**。

个人 Key 实现在 `internal/handler/user_mcp_api_key.go`、`internal/middleware/auth.go:480`：验证 Key 所属用户、实时工作区成员关系、工作区状态和 Key 范围，要求 `X-Tenant-ID`；REST 使用该身份的 capability/KB scope。`MCP_PUBLIC_URL` 仅是返回给客户端的配置字符串，不会注册 HTTP 路由。当前 `internal` 没有 `/api/v1/mcp/personal` 路由实现，也没有把个人 Key 接到 Go MCP Server 的鉴权适配。仓库 Compose 仍带 opt-in Python `mcp` 服务；它不属于本次目标，也不应新增部署。

因此：**不能通过 Nginx 把 personal URL 改写到 `/mcp/<id>` 就宣称同一把个人 Key 可用。** P1 前需确认生产是否有未进入本仓库的 Personal MCP 实现及对应源码；若确实缺失，则先确认最小鉴权/路由适配的开发范围，再实施。复用现有 Key 验证和工具服务，不建第二套账号或凭据。

### 4.2 工具和调用授权

`internal/mcpserver/server.go` 将完整目录注册到一个 MCPServer，`filterTools` 控制发现，`guardTool` 在每次 tools/call 再执行 `ep.HasTool`、端点速率限制，之后才运行 handler。已有服务端调用校验，不是仅隐藏工具。`scope.go` 在文档及知识库访问时调用 ResolveKB，并校验文档所属 KB/租户；此授权逻辑应复用。

| 工具 | 隔离区决定 | 原因 |
|---|---|---|
| list_knowledge_bases | 允许 | 仅实时授权范围 |
| search_knowledge、grep_chunks | 允许 | 检索/Chunk 查询，限制字段长度与结果上限 |
| list_documents、read_document | 允许 | 授权文档元数据及文本 Chunk，不读取任意路径 |
| wiki_search、wiki_read_page、wiki_index | 允许 | 授权 Wiki 查询 |
| ask | 拒绝 | tools_ask.go 明确非只读；创建 session/message，运行配置 Agent，有级联工具及持久化内容风险 |
| add_document | 拒绝 | tools_ingest.go 可调用 URL 导入或手工文本创建，JSON 也可成为文件载荷通道 |
| update_document、delete_document | 拒绝 | 文档写入/删除 |
| 未来工具、未知工具、通用 HTTP/REST 代理、文件/目录/终端/Agent 工具 | 默认拒绝 | 必须显式复审后才进入固定只读注册表 |

`types.DefaultMCPEndpointTools` 用 `!Destructive` 生成默认列表，因此包含没有 Destructive 标记的 ask。不能把这个动态默认集当作隔离区只读集，也不能允许管理员通过端点配置打开隔离区写能力。独立注册表和调用 guard 均须固定允许上述 8 个查询工具；同一用户内网未来获得 ingest 不改变它。

### 4.3 其他边界

* 没发现上述查询工具注册通用 HTTP 代理或客户端任意本地路径读取；文档读取通过授权的知识/Chunk 服务。此结论仅覆盖所审 Go MCP 目录，不保证 Agent/Python MCP 无此能力，因此不开放 ask、Python MCP、Agent/terminal/skill 路由。
* `resource_urls.go` 会在资源绑定/KB 授权后，把引用改写为可供外部访问的存储 URL，可能是对象存储签名 URL 或 `/r/<token>`。已有绑定校验，但持有短期 URL 可独立访问。隔离工具结果应返回文本和文档标识，禁止生成或透传签名凭据、本地物理路径及不受控直链；同时禁止隔离区直达 S3/MinIO/COS/TOS 写入口。不能为图片可用而扩大 8443 路径范围。
* Go 通用 `middleware.Logger` 在 Auth 前处理请求，可能记录前 10 KiB JSON 请求/响应以及非已知敏感 query；目前 privateTraffic 仅覆盖 browser/auth 等。tools/call 的 `content`、`query`、未知参数、clientInfo、错误文本可被写日志，字段黑名单无法保证不落盘。新入口须在窥探 body 之前启用元数据日志模式，禁存请求/响应/参数/查询串/客户端自定 request-id/任意错误原文；APM、代理/WAF 审计和工具内部日志同步检查。

## 5. REST / 文件绕过结论

详见 [接口清单](REST_INVENTORY.md) 和 [静态路由索引](ROUTE_SOURCE_INDEX.tsv)。当前 REST 具备 capability/KB/RBAC 多层保护，但个人 Key 能力可变、部分 JWT 路由不接受 scoped Key，且 RBAC 有配置开关。不得把“当前 Key 没 ingest”当作永久隔离边界。

必须同时满足：隔离入口不转发任意 REST；Go 固定入口拒绝写工具；隔离来源无法绕过到 80、8080、其他 MCP、数据库、对象存储。只拦 multipart 会漏掉 manual、URL、Wiki、Chunk、FAQ、skills JSON source 等路径；只限制 1 MiB 仍可分片编码传输；只禁 POST 会破坏 JSON-RPC。[MCP Streamable HTTP 官方协议](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)

严格的可验收目标是“不允许经 MCP 创建/更新知识、附件、文件、会话或执行任意写动作，并阻断其他入口”。任何可输入检索文字的协议仍会把输入字节送达服务端，不能从内容上数学保证“零代码字节进入内网”；搜索请求还可能交给 embedding/model 服务。应限制查询长度、清除载荷日志和非必要持久化，并核实模型调用/遥测去向。对于必须零字节反向流动的网络政策，交互式 MCP 不满足，需由边界管理方另行确认允许的查询交互。

允许的运维副作用应仅为无载荷计数、速率控制、最小审计元数据及凭据 last-used（现有 server 会更新 last_used）；这些也需列入验收。不得将问题或文档正文写会话、检索历史、缓存键、追踪 span 或调试日志。
