## 两个候选与迁移边界

独立飞书候选仅包含 RC3 所需同步与读取安全修复，不包含 Go MCP 功能移植；联合候选从已保护的 V1 `5468da42...` 逐文件整合。两者均执行正式完整迁移链 **3033 → 3034 → 3035 → 3036**。3034/3035 原 SQL 校验和保持 V1 一致，不跳号、不 Force、不临时拼链、不 AutoMigrate 替代正式迁移。独立候选包含这些 Schema 不等于开启 MCP 或批准历史知识。

3036 增加私有候选、来源状态、持久回执、真实索引候选及数据库写围栏；历史来源不自动登记为已验证。SQLite 仅提供 Schema 与拒绝语义，安全原子发布仅支持通过验收的 PostgreSQL/ParadeDB 共享索引、document KB、平面分块及受控 local 存储。非支持路径不能放宽保护来恢复同步。

## 获得正式发布授权后才可执行

1. 核对候选完整包和业务源码指纹、镜像 ID、依赖与迁移 Manifest，核对正式模型、实际 KB 配置、存储及缓存路径。确认当前数据是否属于已验证范围，不能将合成 HTTP 1024 维结果当成正式模型验收。
2. 保持旧来源停更，暂停来源调度和派发，停止并排空所有旧 APP/Worker 写入者。记录待处理任务、租约、outbox、游标、旧文件和索引数量。正式迁移必须在旧二进制排空后执行，数据库围栏不能代替部署排空。
3. 备份数据库、文件、配置及当前镜像，验证备份恢复。独立核对来源撤权/HOLD 清单，恢复旧备份可能丢失备份后发生的撤权事实，不能恢复后直接开放读取。
4. 在维护窗口执行正式迁移器并确认 `3036 / dirty=false`。失败时保留完整报错及失败库，不 Force 修饰状态；从干净备份恢复到新库并验证，再决定是否切换。不得直接在生产尝试 down。
5. 先以 `FEISHU_SAFE_INCREMENTAL_ENABLED=false`、原停更开关保持启用方式启动新 APP/Worker，确认已有 OA、Portal、Python MCP 和只读访问兼容。生产个人 MCP 仍默认关闭。
6. 获得单独恢复同步批准后才调整来源停更；先少量已确认测试来源完整对账，再恢复积压。核对唯一来源映射、稳定 KID、真实索引和持久回执后才确认游标，监测错误分类、配额、429、长任务、候选占用与 HOLD。

## 故障与回滚

- 解析、模型、候选索引或公开事务失败：保留当前有效版本，失败节点游标不推进；重试通过精确来源和回执恢复，不删除旧正文后重建。
- 权限不确定、缺失或未知来源：持久 HOLD 后再处理清理，正常恢复必须完整来源对账；单篇成功不能解除整个来源 HOLD。可信本地来源删除持久 revoked，真实云端事件可信度另行验证。
- 首选回滚为**关闭新增量写入、保持停更、保留 3036 和加固读取组件**。受限数据的 REST、MCP、文件、模型等读取继续拒绝，拒绝状态不得被开关关闭或旧游标重放清除。
- 已有 HOLD/revoked 数据时，不允许直接将不含读取保护的旧 RC3 APP 接回用户入口。若必须恢复旧 APP/前端，先保持维护隔离、阻断相关读取面，保留最新拒绝状态并核对恢复差异；该旧镜像恢复路径没有真实演练前继续 HOLD。
- 3036 down 在存在 managed 资源/来源时明确拒绝。空隔离库 down/up 通过，只证明允许的空库恢复，不是生产回滚建议。
- 旧匿名 HMAC URL 经过新 APP 时每次复验；已缓存或已下载的字节无法远程收回。对象直链、CDN 缓存和绕过新 APP 的文件路径没有完成收口证明时，不允许宣称撤权闭环。
