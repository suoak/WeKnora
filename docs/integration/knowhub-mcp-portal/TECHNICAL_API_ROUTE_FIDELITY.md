# Personal MCP 技术接口路径的受控输出

实际客户端曾取得接口事实，但最终输出把原文中的根相对 API 路径当作机器路径替换为 `[path omitted]`。入库原文仍保留路径；增加模型推理或重复索引不能恢复已被输出投影删除的字节。

`personal_mcp.technical_api_routes` 默认关闭。只有明确启用后，独立 Personal MCP 路由才采用技术路径投影；已有挂载 YAML 不需要加入新键，`PERSONAL_MCP_TECHNICAL_API_ROUTES=true` 可以显式启用，设为 `false` 恢复原输出投影。该选项不改变 Key、知识库、原文、来源、预算或最终实时授权检查。

第一版只保留同时满足以下条件的原始 ASCII 字面量：

- `/v数字/` 开头，至少两个名称段、以 `/` 结束；每段以小写字母开头，长度和段数有界。
- 同一有界行含明确 HTTP 方法，或同一有界段落具有 URL/URI/Path 字段和方法字段。
- 没有查询参数、片段、编码、路径遍历、文件扩展名、受保护的机器/资源命名空间、长数字串、UUID 形状或长十六进制标识。

完整 URL、下载及文件能力位置仍移除。带查询参数或片段的版本路径整体移除，不能留下参数尾部；裸路径与无法分类的路径仍遮盖。非版本路由分组、完整 URL 中的接口路径和 `/api/` 下的路径不在第一版恢复范围内。不能据此宣称所有技术路径均已恢复。

这是对已经授权的技术正文的纯文本输出分类，不是新的来源证明，也不会解析、打开或请求接口。客户端参数或输出正文里的同名布尔值不能启用该政策。字符串表示和 `structuredContent` 来自同一份投影，防止一种表示仍泄漏旧内容。生成、索引、普通 Wiki 及其他旧读取接口保持原策略。

回归覆盖默认关闭、老 YAML 的环境变量启用/撤回、混合机器路径、编码、下载位置、签名参数、双表示一致及原文周围字节保留。受控 operator 扩展 `TestControlledPersonalRankAB`，仅在显式运行时接受 `Comparison=technical_api_routes` 和 `read_document` 操作，仍要求只读数据库、正常 Key、71 库完整范围核对和原有请求预算；不会启动监听器、Worker 或调度器。比较原投影和候选投影时保留生产排序设置，不把固定文档读取误计为全库搜索命中。

生产启用前应保留实际文档读取的双组输出及当前来源身份，复核路径事实、资源位置遮盖和失败回执，再进行真实客户端验收。单元测试、CI 或能够读取文档元数据均不能代替这项实际对照。
