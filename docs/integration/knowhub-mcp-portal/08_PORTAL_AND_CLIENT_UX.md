# M1 Portal 与个人客户端体验

第二批状态：体验和权限分离规则按 [ADR-001](13_M1_FINAL_DECISIONS.md) 定稿；审批角色实际授权仍 NEEDS_DECISION，未修改前端或 Portal 业务。原工作树已有 MCP 选库与多语言未提交改动，继续保留。

提出者不能批准自己的范围；收权可针对当前版本优先执行，放宽必须重新 propose + 独立 review。管理 UI 未来展示 resource_version/revision、主体、时间、原因和审核范围，不将 system_admin/space owner 自动加为发布角色。公共读取只开放批准正文，与空间进入/管理、任意文件下载分开；默认关闭的 M2 组件只在隔离测试使用，没有可供用户连接的新地址或可复制生产配置。

## Portal

保留 frontend/src/api/portal.ts、空间列表的 discoverable/accessible、申请加入和现有互动逻辑。新增“企业可检索内容”独立字段；“可检索”和“可进入空间”分开显示。员工可搜索公开内容但仍显示不能进入空间，不伪造成员角色。

仅向普通员工显示其可读的 KB/文档数量及是否可检索；受限/待审数量只在授权管理页出现，避免信息侧信道。Portal 列表仍不返回完整私有 KB 授权清单。撤销发布后公共入口及时消失，但个人已有合法授权仍可检索相应知识。

## 管理端

复用空间与 KB 设置页，增加发布审批状态、继承新普通资源开关、KB 收权、文档策略与 grants、审核人/时间/原因和历史。只读预览展示将开放/收紧/待审的确切数量与受控 ID；批量 apply 需要 revision 校验，过期审批拒绝。对外部来源未知 ACL、混合 KB、Wiki 来源闭包缺失提示 HOLD，并显示需要解决的具体原因。

授权测试使用服务器创建的隔离主体或管理员切换到明确模拟角色，结果只投影该主体可见项，禁止把系统管理员 Key 的搜索结果标为普通员工验证。统计来自审计决定与调用耗时，不能收集员工查询正文/敏感内容。

## “我的 MCP”

复用已有个人 API Key 创建、授权空间/KB、client type、轮换和撤销界面，增加个人 Go URL 与八工具说明。新建时清晰列出“企业已批准公共知识（只读）”的显式能力和“本人其他已授权知识”的空间/KB范围；旧 Key 不自动勾选企业能力。轮换只换 token，不改权限。首次展示 token 后避免再显示明文，配置复制不进入遥测/日志。

提供一套 `/mcp/user` URL + Bearer token 连接配置，并为 Codex、WorkMate、Claude Code 提供当前实际验证过的入口/导入方式。具体客户端配置字段和安装指令在 M5 联调时按官方版本核实，本批不提供未经测试的配置模板。用户不需多个团队端点，也不需要创建 Organization。

增加测试按钮：公开知识测试、本人私有授权测试；显示可检索范围、部分失败、过期/吊销/缺少企业能力原因，零结果不等于全部成功。连接凭据不能留在 URL、本地截图或错误日志。删除/下载/ask 默认不出现；MCP 服务端仍独立拒绝未开放调用。

## 身份兼容与验收

OA/SID/飞书关联继续使用现有可信账号绑定，不新增输入工号冒充能力，不等待尚未验收的 SID 功能才允许内部隔离测试。企业员工资格、发布审批角色来源须安全评审；UI 文案不能把 active 用户当作已验证企业员工。

验证各语言、错误状态、只读角色、空间不可进入但可检索、批量审核冲突、旧 Key scope 展示、轮换/撤销、三个客户端连接与工具直调。所有 M5 实测现为 NOT_TESTED。回滚只隐藏新增 UI、禁用个人 Go 路由，不撤销用户原 Key 或修改原 Portal 状态。
