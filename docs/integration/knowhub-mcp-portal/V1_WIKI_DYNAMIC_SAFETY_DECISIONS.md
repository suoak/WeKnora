# 本轮安全实现与候选回滚边界

状态：开发中，尚未冻结或部署正式验收候选。

## 来源隔离

统一解析器仅隔离 `ErrLegacySourceRestricted`，不捕获并吞掉普通数据库、身份、Key 或无法归因的授权错误。明确请求多个 KB 时，已知受限 KB 可以被排除，但不存在或无权 KB 仍拒绝；只剩受限来源时整体拒绝。直接文档/页面/Chunk/文件仍受原权限约束。MCP 内容附加 partial 警告，检索 JSON 状态标注 partial；REST 的有界多 KB 读取使用专用读取路径并在响应标注 `X-KnowHub-Knowledge-Scope: partial`。不改写既有写入和管理接口为部分成功。

来源状态在授权、检索候选、模型输入及输出边界继续复验。无法证明完整输入来源的历史 RAG/Agent 不因读过一个健康 KB 就免除全局保守保护。仅携带可信完整 Wiki 生成闭包的服务端任务，才能把其模型保护限制到实际来源 KB；客户端 Header 无法生成这种上下文。

## 动态私人空间

追加 `personal_scope_mode`，默认 fixed。新页面明确创建 dynamic_all；历史 Key、轮换和修改均不静默升级。动态模式由 Key 的真实 OwnerUserID、账号有效性、Key有效性、每次最新成员关系与原有 KB/共享权限共同决定，不建立第二套成员目录或权限事实。未来新增空间、KB无须重建动态 Key；固定 Key 保留原范围。

mode 只在新建时明确指定，不能通过普通范围编辑把旧 Key 改成动态 Key。平台/租户/机器凭据不能使用动态模式。动态模式不接受 selected KB 限制，避免把“全部”误描述成精确受限范围。

## Wiki 最小可信证明

个人 Wiki 不调用 `GetIndex` / `GetIndexView`，仅使用只读查询，因此缺失索引不创建页面。三工具复用现有工具 schema 与真实个人授权解析器，工具注册和服务端调用白名单一致。

SourceRefs 单独不能证明页面没有混入其他文档。可信 Worker 在生成提示词前捕获完整 KB 输入闭包，核对所有旧 Wiki 输入已有可信证明，版本与当前来源匹配。仅这些服务端生成事务可写入 `wiki_mcp_provenance`；普通用户、模型参数和 HTTP Header 没有认证证明入口。不对历史页面自动回填证明。

生成期间以既有文档 epoch 围栏检测所有内容变更及 ABA；正文读取绑定实际生成输入摘要，避免仅 finalizing→completed 的正常收尾使有效页面立即失效。来源加入后旧页仅依赖生成时的完整闭包；任何原依赖删除、内容变化或当前授权丧失都隐藏该页。页面本身修改也撤销旧证明。

为避免旧/raw Wiki 写入、插入后删除及并发任务混入未证明内容，3037 为 Wiki 生成输入增加局部 KB 变更围栏，所有 Wiki 写入触发器更新它并删除旧页证明。该围栏不是权限目录或飞书第二套全局版本系统；权限仍来自现有 KB/用户/Key/来源。模型网络调用前检查局部围栏及文档版本，旧生成器不得给晚到页面签发证明。

未知/缺失证明的旧页、Draft、Archived 不通过个人 MCP 发布；未知外部来源也不因至少一个引用有权而开放。当前可证明的来源为 KnowHub 本地内容与安全增量已验证的来源；其他云端权限证明不足时保持不可用，不声称已完成所有来源治理。混合来源页必须满足整个生成闭包的最新授权，不能只验证某一条 SourceRef。

目录查询、每 KB 页数、页面大小、结果条数、正文长度、KB数量与请求时限均设上限；截断与隐藏页面必须返回明确状态。重复 slug 只在已授权且已证明的页面之间消歧，不泄漏无权页元数据。
