# 300 / 500人全员首次登录合成容量验收

## 范围与通过含义

员工规模300–500人为USER_CONFIRMED，按上界500设计；300/500人在60秒内开始登录是本轮合成到达率，不是已确认的真实峰值或生产SLA。enterprise_all没有业务人数上限。

APP使用精确f40b1602f镜像，Frontend保留832b6652a，TLS Mock SID使用RS256及独立合成凭据。每笔执行APP授权事务→Mock authorize→callback→Token→ID Token/nonce/UserInfo→绑定或JIT→Access-only结果→auth/me；经实际Frontend代理，不是仓储微基准。负载由HTTP客户端生成，不测浏览器渲染/真人输入速度或真实SID承载力。

所有写入仅在可丢弃 `enterprise_capacity_validation` 数据库，合成账号使用example.test；源数据仅作为该副本的只读基线，真实员工身份从未参与模拟绑定。APP/Mock无公开主机端口、关闭Docker日志；不输出授权URL、Code、Token、Cookie或身份字段。结束移除测试容器与数据库。

APP限制2 vCPU/4GiB，打包机16逻辑CPU；Mock和PostgreSQL共享主机资源，没有将其伪装成生产规格或完全独占基准。压测中默认80/8080与独立18090健康/配置API均200，最终还须比较容器、配置及数据基线。

## 数据库和资源观察

共102次采样；本测试库连接峰值3、active峰值2（含监测查询），Lock等待采样峰值0、users锁等待0、最大采样锁等待0.0ms。只能说采样未观察到等待，不能证明不存在短暂锁竞争。

APP CPU最大采样77.06%，PostgreSQL 34.78%；APP内存抽样：197.3MiB / 4GiB, 205.8MiB / 4GiB, 207.4MiB / 4GiB, 208.7MiB / 4GiB, 209.4MiB / 4GiB, 209.8MiB / 4GiB, 211.3MiB / 4GiB, 213.3MiB / 4GiB, 213.6MiB / 4GiB, 214MiB / 4GiB, 214.6MiB / 4GiB。这些是Docker stats口径，CPU百分比按单核计，APP配额2核；Mock/PG资源不包含在APP限额中。

database/sql客户端池等待计数：**NOT_CAPTURED**。最终合成用户新Refresh为0，JIT成员/管理员权限为0，Token失败对应身份和Session为0；可丢弃库和容器已清理。

连接采样使用本测试数据库的pg_stat_activity，JIT锁观察为pg_locks的users关系等待与pg_stat_activity的Lock等待时间，不读取SQL文本。Docker stats记录APP/PG的CPU和内存摘要，采样不能证明没有短暂尖峰。

源码审计：主PostgreSQL的database/sql池仅设置MaxIdleConns=10和连接寿命10分钟，没有显式SetMaxOpenConns；默认最大打开数为0（不限制），不能误引用Doris池的20作为PG上限。本轮指定f40镜像不修改该行为。生产需根据APP副本、PG max_connections、其他业务余量和峰值明确连接上限及监控方案。

database/sql Stats的WaitCount/WaitDuration/InUse没有现成导出端点，本轮标为NOT_CAPTURED；pg后端与锁采样不是这些客户端指标的替代品。正式发布评估应补齐池等待遥测或采用经验证的等价观测方案后确认连接预算。

## 正确性与残余风险

首次执行的10个HTTP场景功能断言均通过，但外层验收末尾错误断言整个副本的Refresh记录总数为0，因原库继承的24条已撤销历史Refresh而FAIL。原始FAIL收据、行号、合成结果和定向查询保留；这不代表本轮签发了Refresh。只读复核显示新合成账号Refresh为0、历史有效Refresh为0。修正验收为“本轮合成用户新Refresh为0”，并对所有10场景重新执行；未改APP或删除历史记录以使测试通过。最终结果以前述表和最终收据为准。

只在结果满足成功/预期安全拒绝断言后判功能通过；Token200不是完整业务成功。Mock计数应为4400次authorize/Token、4300次UserInfo（100笔预期Token拒绝）、重复/过期Code0；每笔只兑换一次。检查零Refresh记录、JIT零成员和管理员标记，以及到期重登user_id保持。

本轮结果只支持这些合成场景在所测环境中的功能/吞吐观察。最终生产容量仍为待确认：实际最忙一分钟人数/突发分布、新旧账号比例、SID真实延迟/并发/429限流、正式资源规格、APP副本/连接预算、可接受P95/P99和错误率。没有以本轮结果批准全员上线或调用真实SID批量压测。
