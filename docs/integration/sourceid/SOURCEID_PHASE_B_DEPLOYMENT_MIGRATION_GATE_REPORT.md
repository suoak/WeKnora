## 安全部署与回滚

1. CI 全通过后，按准确 Git SHA 归档构建 app/frontend，检查镜像 revision 标签。
2. 对当前 Compose、模式配置、旧镜像和数据库做受保护备份；验证 pg_dump 目录可被 pg_restore 读取。
3. 只替换 app/frontend，使用现有测试数据库和数据卷。由已验收的标准迁移器执行两个待办迁移，不使用 Force、不跳过 003025。
4. 迁移完成后恢复 `AUTO_MIGRATE=false`；协议验证模式保持 true，身份契约、邮箱绑定、自动绑定和统一登出保持 false。
5. 核对 80/8080、本地登录、知识库、MCP、飞书权限与未配置状态、失败回调，以及其他服务容器 ID。
6. 升级失败时恢复备份 Compose/旧镜像。首选保留新增表和迁移版本，由旧版在 AUTO_MIGRATE=false 下运行。数据库备份作为灾难恢复材料，不自动覆盖现有数据。

003025 down 会删除飞书授权/导入记录及应用设置；003026 down 会删除关联审核和审计记录。因此实际库不以执行 down 作为常规回滚手段。回退 SQL 的测试仅在一次性数据库夹具执行。
