# OA验收资源夹具、网络隔离与会话安全补充

日期：2026-10-16。本文是待审批实施材料；本轮没有切换实际业务网络规则、身份门禁或真实SID登录。

## 1. 允许与禁止资源夹具

允许资源：批准的既有空间内一个新测试知识库，纯合成文档至少包含可精确核对的问答段落。必须经过现有知识处理流程完成解析、建立检索索引，普通测试账号实际读取内容并检索命中；仅数据库插入知识库或文档元数据不算完成。

禁止资源：另一测试空间内真实存在的合成知识库，员工无该空间成员关系，且无组织、Agent、知识库共享或系统级旁路授权。用受控owner确认资源存在，再以普通用户读取并断言403/按防枚举策略404；随机不存在ID、同空间第二个KB均不能代替。

此前聚合仅一个空间、有效KB为0；未发现可直接复用的跨空间对照。最小额外夹具建议另批：一个独立资源隔离空间、一项禁止KB、一份无个人信息合成文档；测试员工不加入隔离空间、不成为其owner。既有owner权限不修改，资源准备者和清理人另行指定。当前不创建第二空间。

其他Compose项目或数据库中的资源不能直接拿来当作本实例的跨空间对照，否则在本库找不到ID只证明不存在。必须在同一受验收APP/数据库内存在两个不同空间的资源。

写入与回滚单位：记录每个新KB、文档、空间ID和摄取任务ID，仅在保护清单保存。失败先取消该夹具任务，再通过现有业务删除接口按明确ID清理文档/索引/KB；最后确认隔离空间无其他资源或用户后另批删除。不删原卷、原历史KB、员工账号或审计记录。

知识库真实解析与检索依赖可用的已批准模型/处理组件；本轮不读取模型密钥。若相关能力不可用，标为NOT_READY，不能以Mock解析当作测试机实际检索成功。

## 2. 测试机实际入口只读核查

证据：[入口与权限收据](evidence/network-isolation-readonly-20261016.json)。当前主业务Frontend80、APP8080均发布于0.0.0.0；业务Docker网络有前端172.28.0.6、APP172.28.0.2，业务容器未记录全局IPv6地址。

还存在其他项目的18080/18081/18082、MCP8082等发布入口，部分同时监听IPv6；18182为loopback旧隔离前端。它们是否提供到当前APP/认证入口的旁路，不能仅凭端口号断定，实施前必须逐项核对代理上游、主机路由和访问控制。SSH22不应被隔离方案误断。

最终只读HTTP配置查询：80/8080返回OIDC enabled=true；18080/18081/18082/18182返回enabled=false；8082该路径返回业务401、OIDC状态UNKNOWN。见[最终现场收据](evidence/account-preparation-final-readonly-20261016.json)。这是无凭据配置接口结果，不是SID Token状态，也不能代替虚拟主机、其他路径和IPv6旁路检查。

sudo非交互读取iptables/ip6tables/nft规则未获允许，当前防火墙链内容为UNKNOWN。这不证明没有防火墙，也不允许为查看规则而用特权容器挂入宿主网络。未输出规则全文、环境变量或HTTP凭据。

## 3. 实际隔离环境预演

证据：[隔离Docker实验](evidence/network-isolation-lab-20261016.json)。新建独立前端双栈bridge及内部后端bridge，Nginx只允许指定实验源；没有连接业务网络。使用现存不可变Frontend镜像，不拉取、不构建、不修改原容器。

| 实测路径 | 结果 |
| --- | --- |
| 允许源IPv4 → 实验前端 → 后端 | HTTP200，返回纯合成标记 |
| 禁止源IPv4 → 实验前端 | HTTP403 |
| 允许源IPv6 → 实验前端 → 后端 | HTTP200 |
| 禁止源IPv6 → 实验前端 | HTTP403 |
| 前端网络内禁止源 → 后端私网IP | 无HTTP响应，连接拒绝/超时 |
| 后端本机健康检查 | 成功 |
| 宿主loopback随机发布端口绕过允许源限制 | HTTP403 |
| 清理回滚 | 仅移除所创建容器/网络/合成配置；原运行容器ID集合不变 |

实验使用loopback随机端口32782，结束已移除发布容器。Docker为新实验网络生成自己的规则属于实验范围；未编辑既有业务规则或宿主防火墙策略。初次实验将前端也设为internal，Docker未创建期望发布映射，断言失败后已准确清理；改为独立普通前端bridge、internal后端后上述检查通过。

**这是网络分段及源限制机制预演，不是实际80/8080隔离验收。** 实验允许/禁止客户端不是获批员工工作站或真实未授权局域网来源，不能把这组结果升级成真实来源证据。

## 4. 待批准的实际隔离切换与回滚

首选由有权限的测试运维基于实际Docker转发拓扑实施限时过滤，不修改生产网关。批准前应列出工作站实际到达源（包括代理/NAT）、全部入口、IPv4/IPv6、内部前端到APP及健康检查路径。

1. 保护备份当前规则和相关代理配置，记录唯一变更集、维护时段、执行人、独立回滚人及SSH恢复通路。先校验而不应用。
2. 创建本次专属规则链/配置段，覆盖主机INPUT与Docker FORWARD实际经过的路径；若采用DOCKER-USER，必须确认该Docker/防火墙后端实际使用它及DNAT前后端口语义。不能单独依赖UFW界面或某链存在。
3. Frontend80仅允许批准来源；APP8080阻止绕过前端的外部访问，仅保留批准诊断及内部前端连接。IPv6无须时应明确拒绝相应认证入口；其他代理若能到当前业务APP，必须一并限制。
4. 在企业门禁关闭状态，从批准工作站实测前端/API/callback可达，从独立未批准工作站实测80、8080及其他旁路被拒。拒绝来源不能只是同一客户端换Header；不得伪造Host/Origin/Referer绕过SID。
5. 正常内部代理和健康检查需实际通过；Docker容器间直达风险、同机其他操作者和SSH转发能力也要纳入维护窗口控制。现有第三方来源不能测试时记NOT_VERIFIED，禁止开门禁。
6. 配置仅限该维护窗口；发现旁路、非批准认证流量、规则失效、负责人离线或超时，立即关闭身份放行并撤销测试Session。
7. 收尾先恢复企业门禁并验证旧Token拒绝，再恢复原网络配置；仅删除本次唯一命名规则，不flush全局规则、不重启Docker、不prune。对照备份检查原业务/SSH/IPv6路径恢复。

本轮未申请或执行上述实际切换。真实来源验证、旁路代理核查和规则读取权限仍是明确阻塞项。

## 5. 首期10分钟无Refresh候选的使用体验与限制

候选Access/Absolute/Idle/AdmissionMaxAge均10m；未批准、不写入现场。参见[正式待审批表](SOURCEID_FIRST_LOGIN_SECURITY_DECISION.md)。到期后的下一次受保护请求将被拒绝，前端需提示重新OA登录；已有SID SSO可能不要求再次输入密码，但不能据此假设会重新执行准入，仍需SID正式确认。

当前Vue的共享401处理可能先尝试一次Refresh；authorization模式后端必须拒绝续期，前端随后清理登录态并转/login，用户再点击OA。不能把这次前端尝试当作会话续期成功，也不能宣称已有友好的“会话到期”专用提示或自动恢复草稿。改善提示可另行评审，当前不修改认证流程。

新的检索请求在Session过期/撤销后应拒绝。**已开始的流式回答或长请求通常只在入口做认证，当前没有证据证明会在过期或撤销瞬间中断全部在途流。** 因此不承诺10分钟硬截断所有输出；需批准最长请求/流的附加风险窗口，或另行实现并验收周期检查/取消。用户退出时前端取消流的行为也须实际验收。后台文档处理不是靠续期用户Session维持，不能为测试撤销会话而自动删除既有处理任务。

待安全负责人决策：最长流式请求上限、到期时是否允许当前流完成、前端保留未提交问题/部分答案的交互要求、重新授权后如何恢复上下文。当前没有修改流处理或取消机制，不能声称这些体验已真实验收。

## 6. 定向失效操作方法

- 用户本地退出：走现有退出业务方法；当前设备Session及其派生Token应失效，退出后以旧Access请求auth/me必须拒绝，不宣称注销SID。
- 管理员单Session：已有`userRepository.RevokeSourceIDSession(ctx, sessionID, userID)`在同一事务撤销指定source_id_sessions及其auth_tokens；从保护审计清单取得Session/user ID，只调用受审内部操作器，不把JWT/邮箱当查询参数。该方法不是已发布管理HTTP页面，执行人、受控调用手册和权限须先指定并用合成Session验收。
- 绑定撤销：现有`sourceid-binding`工具按review ID执行revoke，使用真实操作者/批准引用，覆盖身份会话并禁止自动重绑；不读取员工字段或Token。影响所有设备，需对应批准。
- 账号准备器`--detach`：只适用于其准备操作，拒绝已有SID身份/审核/会话的账号；它不是统一登出工具，不能用来绕过绑定撤销。账号不删除，新建夹具账号仅停用。
- 仅恢复protocol_only/绑定开关不等于所有已发Token已撤销。收尾必须定向撤销、auth/me拒绝断言、保留审计。
