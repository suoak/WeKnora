### 当前代码与全角色目标的差距

核查部署提交 `431226c3b1bd5338ec06c1bd0520e637d5fed398`，不是根据工作区未验收改动推断：

- `internal/application/repository/sourceid_binding.go` 的 `ordinarySourceIDAutoAccount` 明确拒绝 `IsSystemAdmin`、`CanAccessAllTenants`、owner/admin 成员关系及组织管理员。
- `ResolveSourceIDAutoEmailIdentity` 首次自动批准调用上述检查，因此目前不会自动关联原管理员账号。
- 已批准绑定会先被解析，故已有审核绑定的管理员与“首次自动关联管理员”是不同分支。`TestSourceIDEmailRJGHReviewLifecycle` 已有保留管理员标志、原 user_id/tenant_id 的合成测试，但不能据此宣称首次管理员自动关联已实现。
- 单账号准备器专供普通测试用户，不用于降权或重建旧管理员。

需要单独完成最小代码变更：将“必须为普通角色”从首次关联资格中移除，采用经批准的全角色关联政策；新增系统管理员、owner、组织管理员、跨租户管理账号首次与再次登录、保留全部原权限、撤销及并发测试。不得移除账号启用、邮箱唯一匹配、身份唯一约束、issuer/RJGH/sub 冲突、撤销禁止自动重绑等检查，也不得修改原账号角色。该功能差距不是配置切换能够解决。

用户的全角色需求不等于本轮已批准关闭协议门禁、切换网络隔离或进行真实身份写入；本轮未执行这些操作。

本地专项验证通过：使用已缓存 Go1.26.8 工具链运行 `TestSourceIDEmailRJGHReviewLifecycle` 与 `TestSourceIDAutoEmailBindingRejectsExceptionalAccounts`，结果 PASS（仓库测试 2.307s）。两项均使用合成数据，分别证明现有人工审核后的管理员绑定保留账号标志，以及现有自动路径仍拒绝异常/高权限账号；不是全角色自动关联新功能通过证明。初次工具链自动选择受 GOSUMDB=off 阻止，改为直接调用已安装工具链，未下载依赖或修改项目配置。

## 4. 建议的两条验收路径

1. **原账号与原知识库保留验收：** 原 weknora 隔离副本最贴合需求，保留原管理员 user_id、租户与 ACL。先验证完整迁移与全角色自动关联代码，再在独立批准后验证 OA。当前验收库保持原状。
2. **普通账号最小闭环：** 继续使用当前已准备 viewer，建立非敏感合成知识库和另一空间实际存在的禁止访问资源。若复用旧内容，先确认内容授权，通过受控业务导入；不整体合并 users、身份、会话和模型凭据。这条路径不证明原管理员账号的权限保留。

副本实施步骤（本轮未执行）：

1. 复核空间、磁盘容量、端口与批准范围；保留当前 80/8080 与所有原卷。
2. 生成受保护的一致 DB 与文件快照，使用独立 PG、文件副本、缓存/索引及内部网络，禁止混用原卷的可写路径。
3. 在副本 APP 启动前关闭 SID/邮箱绑定、外部同步与后台任务；隔离出网。复制的业务会话/API key/JWT 不应直接作为有效测试凭据使用，按审批做副本内撤销/独立密钥准备；模型凭据由受控流程处理，不导出给 Agent。
4. 使用固定目标版本完整迁移副本，验证 clean 状态、数据数量、原 user_id/tenant_id/角色/ACL 的私有一致性，以及非空文档读取与授权检索。
5. 在全角色关联实现与合成测试通过后，分别验证原管理员和普通 viewer。管理员权限测试不能用普通用户的“禁止访问”预期替代，应按原管理策略核对；普通账号跨空间对照资源必须确实存在且无间接共享。
6. 真实员工登录仍须独立批准、会话策略及 SID 时效契约完成，并验证流量隔离。失败仅撤回副本/候选，不覆盖或删除原库、当前验收库及卷；清理需定向核对后执行。
