# 正式一次性全员开放操作卡

**待发布批准；本轮不可执行生产命令。** 正式一次性向公司全员开放，不限制事业部/部门/组织/角色，不设计线上10人、100人再扩大的阶段；所有发布前校验在独立环境完成。组织字段校验已从范围删除。

## 发布前

1. 归档最终代码、四项CI、不可变APP/Frontend镜像ID、数据库迁移清单及恢复演练结果。独立环境f40b1602f/DB3029已技术验收，生产现场仍待单独授权核查，不把独立部署当作生产已发布。
2. 核验公司全量历史归属批次及冲突汇总；冲突账号不可错误继承旧权限，其余账号不因组织、角色或人数受限。确认SID应用实际允许的企业账号类型、公司级JIT批准政策和完整精确邮箱域集合；支持多个正式域，无组织字段准入，不使用Mock证明。
3. 确认正式会话/来源参数、责任人和真实批准引用，按全公司人数、峰值、生产规格与SID限流填入容量和监控阈值。原300–500人不是公司规模，未填齐不切换。
4. 获准后核查实际生产schema，不假设与测试库一样。按标准migrate完整执行批准链，不跳版本、不手改schema_migrations；审计原用户、角色、文档、索引及ACL私有基线。
5. 冻结认证/绑定及业务写入、外部同步和后台写任务，制作同代DB与文件、配置和镜像备份。验证备份可恢复，确认维护公告及回退决策人。

## 维护窗口内一次性切换

6. 部署最终经过验收且支持JIT的版本及固定镜像，执行已批准迁移；不临时混入未验收代码。
7. 通过受保护进程执行全量归属dry-run，确认汇总与数据负责人签署一致，再批准apply；重放应无新增。实际迁移和数据变更均留审计。
8. 核对回调及同源浏览器路由、前端API代理、正式TLS与端点，不修改SID批准callback来逃避路由问题。
9. 加载正式enterprise_all及公司级JIT政策，一次性对所有符合公司企业条件的员工开放；没有线上个人试点名单、部门/角色区别或人数阈值。继续保留全部OIDC验证、冲突拒绝和原知识库ACL；新账号无默认空间/敏感知识/管理权限，公共知识仅按共享权限授予。
10. 首轮检查新旧账号、原管理权限及多空间读取、无Refresh、退出和撤销；这是一次性开放后的健康核验，不是部分员工先开放的灰度推广。

## 监控与紧急处置

11. 联合监控OIDC各阶段、签名错误分类、绑定/JIT成功失败、拒绝及冲突、auth/me、Session到期/撤销、DB池与锁、来源新鲜度与积压。不得收集Token、Code、Cookie、完整URL、员工原始字段。
12. 错绑/越权确认即紧急关闭OA业务与JIT，定向撤销；系统性故障依批准阈值止血。保留原本地账号可用性，但JIT账号没有可用本地密码，不能以回退密码登录宣称其已恢复。
13. 使用发布前固定APP/Frontend回滚pin，保留新表、绑定和审计，不自动down。数据库/文件灾难恢复须重新审核新增写入差异，不能无条件覆盖。
14. 对照原账号/权限/知识库基线、数据库clean、配置及外部同步状态复验。明确恢复结果、遗留数据差异和后续负责人。
