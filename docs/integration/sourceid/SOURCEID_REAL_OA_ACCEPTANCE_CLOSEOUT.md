## 2. Trace 缺口、根因与最小修正

### 已证实的缺口

1. `oidc_transactions` 同时保存授权事务和前端登录结果交接。前者 nonce 非空，后者为空。
   旧查询未区分，会把交接结果误算为第二笔 authorize；此前已修正为 `WHERE nonce<>''`。
   没有读取 nonce 原值或结果载荷。
2. `PilotBusinessAdapter.poll` 原先先读取日志到内存，再查询数据库，最后处理日志。
   `BusinessMonitor.transactions` 首次看到 consumed=true 就提前停止。普通 SSO 快速完成时，
   授权保存、callback、消费可能发生在两个轮询之间，已读到的阶段证据随之未被保存。
   此竞态可由隔离 Mock 稳定复现。
3. 本次受保护收据显示 transaction_bound=false、authorize/callback trace 均缺失、阶段事件和
   HTTP 事件均为 0。缺少当时事务快照，不能断言本次一定由上述竞态触发，也不能排除其他关联异常。
   不推测操作者、不倒推 Trace、不把缺失 callback 解释成 Token 失败。
4. Session、Access、绑定和业务网关各有记录，但当前没有持久化、经服务端验证的单一
   authorize→callback→Session 关联键。网关 request_id 不能直接冒充 OIDC Trace；
   同一 user_id、时间接近或同一来源地址也不足以唯一证明事务关系。

### 本轮已完成的最小采集修正

- 先保留固定白名单的未关联阶段计数，再执行数据库关联，避免关联失败抹掉已有观察。
- 明确输出 FIRST_OBSERVATION_ALREADY_CONSUMED、MULTIPLE_NEW_AUTHORIZATIONS 等固定原因。
- 首次即已消费但无法证明归属时标记 INCOMPLETE，不宣称协议失败或完整 PASS。
- 未关联计数不含身份字段、原始请求或 Trace 值，不能用于填补已关联阶段 PASS。
- 保留真实第二笔授权冲突拦截、体积限制、默认不执行与敏感字段丢弃。

Windows 和 Linux 隔离副本各 **49 项校准 PASS**。Linux 测试仅上传到私有隔离工具目录，
没有更新运行中的采集器或 APP。没有新 CI、候选 APP 或部署结果的宣称。
本轮尝试重跑既有 Go 会话测试时，本机 Go toolchain 被 `GOSUMDB=off` 阻止校验，未实际执行；
没有改变工具链或将其写为通过。

### 完整关联仍需的受控验证

新计数能防止丢证据，不能单独修复快速消费后的唯一关联证明。下一版采集器应在隔离 Mock 中
校准：消费前取得授权元数据并缓存；仅凭唯一授权、完整有序且同一 callback Trace 的安全事件
组合形成关联；首次已消费且缺少持久证据时仍 INCOMPLETE。若轮询仍不能可靠覆盖，最小 APP
观测扩展应由服务端生成随机、不承载身份内容的关联 ID，贯穿授权事务、callback、Session
审计和业务请求，仅输出固定阶段与结果。需先独立提交、Mock/并发/安全回归并等待部署批准，
不得靠修改当前运行 APP 或读取登录结果里的 Token 补齐。
真实链路验证必须另行批准一笔新认证；本轮不自动补测。

## 3. 剩余安全测试安排

### A. 跨空间拒绝

当前库只有 1 个有效知识库，且被测账号为系统管理员，因此目前没有可直接宣称应 403 的
跨空间资源。先只读核对实际系统管理员、跨租户、共享及 ACL 规则，不为获得 403 降权。
在隔离副本中准备两个真实存在的合成空间及非空知识库、一个只有第一空间 viewer 权限的
合成账号；确认第二空间没有公开共享、显式授权或间接成员关系。验证第一资源可读、第二资源
按实际 API 契约返回 403 或隐匿式 404，且不能读取文档、下载、分块或检索正文。
系统管理员若按设计应有权访问，则其访问成功不构成越权，也不能标作负向测试通过。
需使用真实普通员工时单独授权，不修改当前管理员。

### B. Access / Idle / Absolute / Admission 到期

在隔离服务/数据库和合成 Token 下分别推进四种期限，避免 60 分钟的多个期限同时到期使原因
不可区分。覆盖到期前、边界、到期后及并发请求；可控时间只作用于测试实例/合成记录，
不更改服务器时钟和真实 Session。每种到期后检查 ValidateToken、auth/me、受保护知识 API、
SwitchTenant、Refresh 均拒绝；刷新页面不恢复服务端状态。
合法 SwitchTenant 必须保留同一 Session 绝对截止时间；策略变更及切回不得恢复已撤销记录。
对仅因 TTL 过期的记录检查后续策略不能延长其已落库期限。
复用 `sourceid_local_session_test.go`、`sourceid_sso_test.go`、
`sourceid_verified_email_test.go` 和实际 API Mock 夹具；不要把旧 CI 或源码审查当成本轮重测。
原 Access-only、撤销、缺少 session_id 拒绝继续保留。
本轮只完成测试安排与既有覆盖审查，新的到期执行结果仍待隔离测试，不标 PASS。

### C. 退出与撤销

本次数据库核验已完成；不删除原用户、身份绑定、审核或审计。
旧 Access 重放和管理员/绑定撤销竞争可先用隔离合成凭据验证。
真实 Access 不提取、不转发到 Codex；如需真实客户端重放，须另行受控授权。

## 4. 第二个真实 JIT 用例的前提

- 独立批准该员工、一次认证、用户/绑定/Session 写入及保留/清理责任人。
- 受保护只读检查确认不存在历史账号（含软删除）、同邮箱、RJGH/sub 绑定、撤销、停用或
  已知归属异常；关联失败不得降级 JIT，不能清除原管理员绑定模拟新用户。
- 确认 SID 应用实际企业账号类型和获批完整精确邮箱域集合，支持公司多域；不加部门限制，
  不只凭未经验证的邮箱域作为可信企业身份证据。
- 真实 JIT 政策批准及真实政策版本、Access-only 期限与普通 SSO 风险接受齐备。
- 服务端采集与唯一事务归属先经 Mock 验证；JIT 与现有账号测试分开授权，不自动第二次登录。
- 断言用户数只增加 1、后续同身份不重复开户、tenantless、管理员/跨租户标记关闭、无默认
  成员关系/敏感知识库 ACL；Portal 与 auth/me 正常且未授权知识访问被拒绝。
- 退出/撤销、无 Refresh、异常回滚完整；保留真实开户与绑定审计，不自动删除员工。
