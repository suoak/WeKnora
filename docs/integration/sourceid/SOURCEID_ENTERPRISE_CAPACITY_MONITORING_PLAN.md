# 全员首次登录容量与监控

更新日期：2026-10-17。正式一次性向公司全员开放，不通过线上人数分批规避容量验证。本报告区分已测数据与尚待输入的公司级生产目标。

## 已有证据

独立打包机 PostgreSQL 合成：1000条归属导入2932ms；10000条20123ms；1000次索引检查302/296ms。12路同身份首次绑定最终只有一个绑定，递增更新/停用撤销及唯一约束通过。以上不是SID端到端登录QPS或10000并发结果。

JIT候选 f40b1602f 的最终Linux隔离/race样本通过：24个不同新员工、8路并发，注册仓储总耗时528ms、P95约193ms；另有同身份12路竞争且仅创建一个用户。此为仓储关键路径样本，不含真实SID网络、完整前端和所有注册服务开销，不作为生产QPS承诺。

早期实现先计算再废弃本地密码hash，在同类2CPU/race样本中24个注册约30183ms、P95约10117ms；现已改为内部外部认证专用注册标记，不为不可用密码执行bcrypt，普通密码注册仍保留bcrypt。不同运行受负载/缓存影响，不承诺固定提升比例。

新JIT注册为避免与其他注册并发造成规范化邮箱歧义，使用短事务 users 表写锁；已有历史账号登录不走此锁。新开户及JIT身份快照续接仍需测锁等待、CPU与数据库池；不能用旧账号索引查询速度替代新员工开户吞吐。当前没有生产容量PASS声明。

## 必需规模输入

原300–500人是此前规划规模，历史测试按上界500设计；**不能代表全公司员工总规模或当前生产容量目标**。全公司预计可登录员工数N、活跃用户比例及最忙一分钟登录人数B目前UNKNOWN，待公司业务/运维负责人确认。enterprise_all仍无固定业务人数上限，不以历史压测规模限制公司员工登录。

已有账号/新员工比例、集中首次登录与集中到期重登的峰值/突发分布、预计已有SSO比例、生产APP副本/CPU/内存/PG连接预算、SID Token/JWKS/UserInfo限流与并发契约仍待确认。不提供员工名单或原始身份数据。成功率、P95/P99、可接受拒绝率和资源余量由公司级业务/SID/运维负责人确认，缺少输入不宣称生产容量PASS。

目标到达率可从B/60估算，再按批准余量、重试禁止策略及新旧用户比例设计新的公司级合成测试；不在缺失输入时编造QPS目标，不重复已通过的同参数测试代替公司容量评估。会话到期集中重登也纳入负载，不以Refresh减轻压力，因为首期禁用Refresh。

已在独立环境执行的合成容量场景：300人在60秒内发起首次登录（平均5次/秒），以及保守规划场景500人在60秒内发起首次登录（平均约8.33次/秒）。这两个数是测试到达率假设，不是用户确认的实际峰值或生产容量PASS。每次登录会产生多笔HTTP请求，不能把登录发起率等同于总HTTP QPS；同时在途数量还取决于SID与应用耗时。

本轮已分别完成已有账号首次关联、新员工JIT、混合比例、模拟SID延迟/429/401和集中到期重登的10个完整HTTP登录场景。最终复测4300成功、100预期拒绝，新增Refresh0、重复兑换0；首次历史Refresh统计口径错误和复测原始记录均保留，详见[300/500容量验收](SOURCEID_JIT_CAPACITY_300_500_REPORT.md)。生产余量、成功率与延迟门槛仍需负责人确认，客户端池等待计数标为NOT_CAPTURED。

## 独立环境负载验收

使用纯合成数据和Mock SID，分别覆盖：已绑定登录、已有账号首次绑定、新员工首次JIT、同身份竞争、混合角色/多空间SwitchTenant、冲突与拒绝、到期/退出/撤销。测正常及模拟SID延迟/401/签名失败/超时，验证无Code重试、无重用户、无权限变化、无Refresh。

按目标逐步增加**离线合成**负载至批准余量，不在生产按人员灰度。记录实际到达率/完成率、P50/P95/P99、失败类别、CPU/内存、DB池/锁等待、OIDC各阶段耗时及服务端请求次数；服务不可用和恢复后再次校验完整性。测试结束不留可用合成会话。

SID Code寿命90秒且一次兑换；回调到Token的排队必须留充分余量，不将90秒当作每笔回调仍剩90秒，也不以本地state创建时间推断SID Code签发时间。过期或失败停止，不靠重用Code或自动重复授权掩盖过载。

阈值和可接受延迟由业务/SID/运维/安全负责人正式确认。测试必须在与目标接近的资源规格下复现；CI runner只能用于功能和有限竞争样本，不能出具生产容量承诺。

## 监控与告警

- 登录阶段：authorize/callback/state/Token/RS256/JWKS/nonce/UserInfo/绑定或JIT/Session；只记录固定分类和Trace关联。
- 正确性：错绑与越权为零容忍事件；重复账户、绑定冲突、停用/撤销拒绝及异常增长计数。
- 会话：无Refresh、到期和空闲拒绝、本地退出、定向撤销、SwitchTenant越权拒绝。
- 来源：最后真实核验时间、即将过期人数、源同步心跳/积压、部分失败与幂等重放；严禁自动延长verified_at绕过故障。
- 运行：SID延迟/限流、APP健康与CPU、DB池与锁等待、磁盘、备份、索引、DNS/TLS与网关。

日志白名单、体积/保留期限、访问控制及值班负责人在发布审批时填写并演练。发生严重身份/权限问题先关闭OA业务与JIT并撤销Session，再定向回滚；不清理审计来隐藏事故。
