# RC3 生产执行前最少确认项

本轮只修复合并门禁、部署现有测试环境，不授权合并 main 或生产操作。生产保持 RC24、DB3023 和原 Python MCP。业务接受旧来源短期停更的决定有效；不能据此编造执行窗口、负责人或恢复期限。

| 待确认项 | 需要的实际信息 |
|---|---|
| 维护窗口 | 开始/结束时间、允许停机时长、窗口批准记录 |
| 停更期限 | 预计恢复时间、最大允许陈旧期限；到期未修复时由谁决定继续暂停/限制使用 |
| 执行与应急人 | 业务负责人、运维执行人、技术负责人和可及时响应撤权的联系人 |
| HTTP OA 风险接受 | 生产安全负责人明确接受授权码、Cookie、Bearer/localStorage Token 与页面篡改残余风险的记录；不写成 HTTPS 等价或安全合规 PASS |
| OA 正式配置 | 真实生产审批引用、`time_limited` 生命周期及批准的 RFC3339 截止时间、正式凭据受控位置；不得复制测试 `continuous_test` / 测试实例标记或虚构长期期限 |
| 镜像发布触发关系 | 运维确认 main/v* 推送镜像后，是否存在外部自动拉取、Watchtower、Webhook、systemd/cron 或其他自动更新；仓库没有 SSH 部署不能代替此确认 |
| 正式发布与回滚 | 锁定源码/镜像、Windows 上传校验、备份/RPO、全部旧 Worker 排空及防重启证明、迁移/回滚授权；未批准前不执行 |

## 暂停与紧急撤权

清单仍为 2 Wiki、5 Drive、354 Knowledge 的审查时点快照，见 `RC3_BUSINESS_SUSPENSION_CONFIRMATION.md`；窗口前重新只读对账。保留 Knowledge/KID、Chunk、Embedding、Wiki、原文链接及完整来源配置/游标/调度。不清理队列，不用旧 Worker 与新 APP 同库混写。

新增、修改、源端删除与撤权在停更期间不自动同步。紧急撤权须由联系人立即受理，通过已授权的正常权限/共享管理限制 KnowHub 副本、公共入口与相应检索范围，同时核查 Wiki 派生内容和现有分享。**仅撤销跨空间分享不必然阻断原空间成员访问**，必须逐项验证空间成员、API Key/MCP 和 Portal/RAG 的实际可见性；无法确认完全阻断时进入经批准的维护封锁，不能继续开放等待增量修复。已经被用户读取或下载的副本不能靠后台 ACL 撤回。

## 回滚目标要区分数据库版本

本轮测试升级没有新增迁移，前一测试候选 APP `20497a609866…` 与 Frontend `dfb3c7ea4f25…` 均支持现有 DB3033，可保存为本轮测试回滚目标。回滚不是删除用户或重建知识库。

生产 RC24 不认识新停更屏障，且尚不能假定它可以直接运行在升级后的 DB3033 上。正式发布须选择并验证一个支持 DB3033、理解停更开关的候选作为优先应用回滚目标；原 RC24 镜像仍归档保留。若需回退数据库，按已验证物理恢复 Runbook 在新空卷恢复，不 ForceVersion、不执行未经验证的 down、不覆盖故障卷；明确备份后写入损失和对应批准。没有旧消费者隔离/排空证明，不启动其同步任务。

Python MCP 专项真实调用按用户决定 WAIVED，原生产镜像/服务/配置仍保留。此项不授权 Go MCP 开放或 Python→Go 迁移。
