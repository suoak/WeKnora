# Consumer 健康读取边界的单次完整重验

## 已确认范围

生产诊断记录到 `health_consumer_read_conflict`。这证明完整 Consumer 读取后的原始元数据，在健康 Lua 原子核验时已变化；不能仅据此认定变化只来自正常编码，也不能据此断言某次历史事故的唯一根因。

原实现对该明确冲突立即撤回许可并重建稳定窗口，可能中断合法的长任务。本变更仅处理这一已分类的读取边界，不修改源端权限、知识库授权、身份代际、执行/发布栅栏、签收或幂等规则。

## 判定边界

- 仅带 Redis 服务端错误类型、且完整内容为 `SYSTEM_CONSUMER_READ_CONFLICT` 的健康 Lua 结果允许重验。普通同名错误、未知状态、连接错误、缺失、过期和身份异常均不重验。
- 首次失败的 proof 仅用于前后逻辑身份比较，不能作为稳定样本或执行授权。先在未裁剪 journal 和既有审计 sink 中保存首个失败的安全诊断；写入失败或原 context 到期则关闭。
- 重验重新执行完整解码、唯一 active server、队列订阅、Worker/incarnation、membership、租约、registry/TTL 和原始元数据原子校验，不能只重新 GET/SHA。
- 同一个 Step 的初始和续租前两处读取共用一个本地预算，合计最多增加一次完整读取。成功结果只向原稳定窗口贡献一个样本，不增加超时、不等待、不递归。
- 重验后的逻辑身份必须与首次读取相同。二次失败或身份变化关闭；最后成功健康 proof 与原续租 CAS 之间仍没有 SQL、审计或等待。最终 CAS 冲突仍然拒绝，不重试 CAS。
- 不延长现有许可，不在读取重验时解除 Guard，不删除 trip、恢复旧授权或修改任务状态。旧许可仍受原 TTL 限制；新许可只能由原完整 CAS 产生。

## 验证要求和限制

测试使用独立 Redis、真实 Asynq 和迁移后的 PostgreSQL。正例分别在初始读取及续租前读取注入 SDK 等价编码变化；此写入是明确的隔离 fixture，不冒充自主心跳或远端飞书授权。

负例覆盖第二次冲突、同 Step 双边界冲突、元数据缺失/损坏、membership/incarnation 变化、审计失败/原 deadline 耗尽、journal 失败，以及非白名单错误不重验。原最终 CAS 冲突、真实 Consumer 替换、来源权限和发布回归必须继续执行。

实际长任务继续进行完整 Guard 检查，跨真实自主心跳及多次受控读取边界。只对显式 fixture 写入与请求侧 CAS 做测试同步，所有请求检查仍执行，自主心跳不受此同步控制。该用例不宣称消除请求侧所有微小 CAS 竞争。

Windows 编译和被 gate 跳过的原生用例不构成 SQL/Asynq 验收。Linux 执行结果及失败复测另保留制品；未完成的运行不得写成 PASS。

## 发布及回退

无 Schema 迁移。通过最终源码专项回归、Review 和 main 合入后，仍须校验实际 main 的原生 APP 制品和完整隔离运行。生产回滚必须绑定切换前真实镜像和配置，仅回退 APP/内置 Worker；保留不可变 SQL receipt、journal、trip 审计、原文、Chunk、索引和已接受意图，不恢复旧 Redis/数据库快照，不重放归档任务。
